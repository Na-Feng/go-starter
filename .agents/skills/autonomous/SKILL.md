# 无人值守长任务开发剧本（Universal Agent Skill）

适用于需求已明确的多步骤模块开发，采用**“单分支原子串行 + 确定性门禁 + 独立只读审查 + 脏改动回滚”**防失控闭环：

## 1. 前置校验与单分支隔离
- **规格定稿检查**：确认输入规格（如 `docs/specs/YYYY-MM-DD-<slug>.md`）无明显逻辑矛盾；若需求仍高度模糊，先运行 `spec-check` 定稿后再挂机。
- **单线物理隔离**：基于最新 `origin/main` 创建唯一工作分支 `auto/<slug>`。全流程**严禁直推 `main`**、**严禁多开子分支或并行派发有写权限的子代理同时改代码**，彻底杜绝内部合并冲突与迁移撞号。

## 2. 拆解有序原子清单（`.tmp/tasks-<slug>.md`）
- 按跨端依赖顺序（`SQL 迁移与权限种子 -> Go 模块与单测 -> OpenAPI 契约与 make gen-api -> Web/Taro 页面与 feature-map`）拆解为粒度可控（每条预计改动 `< 300 行`）的有序任务 `T01, T02...`，写入已忽略的 `.tmp/tasks-<slug>.md`（状态：`[ ]` 待办、`[x]` 完成、`[!]` 熔断跳过）。
- 开工前用只读视角自检一遍任务顺序：确保任意 `Ti` 完成后仓库都能独立编译并通过全量检查。

## 3. 挂机防卡死铁律
- **零提问记假设**：执行期遇到非高危的细节未定义项，**禁止停下来等待人工回复**——直接采用最稳妥的默认实现，并将决策追加到 `.tmp/tasks-<slug>.md` 的 `Assumptions` 小节，最后随报告集中呈报。
- **不吞错、不越界、不堆巨石文件**：严禁空 `catch` 吞掉异常、严禁规则豁免注释或弱化断言；业务单文件严格控制在 500 行以内；一旦任务必须修改受保护底座（`internal/kernel/`、`arch_test.go`、`eslint.config.js`、`.github/`、`.agents/`）、引入新第三方包或执行破坏性 SQL（`DROP`/`TRUNCATE`），立即触发**全局硬熔断停机**。

## 4. 逐条原子串行循环（针对每条 `Ti` 依次执行）
1. **实现与确定性门禁**：完成 `Ti` 编码并执行受影响端的 `make check-*`（涉及 SQL/仓储必跑 `make test-int`）。
   - **2 次受阻会诊机制（Advisor 视角）**：若同一编译/测试报错连续修复 **2 次** 仍未通过，**禁止直接第 3 次盲改打补丁**——必须先切只读视角（或调起只读子代理）完整梳理调用链与类型约束定位根因，再做最后 1 次修复。
2. **无状态自包含只读审查（上限 3 轮）**：门禁全绿后，启动一次独立只读审查，传入**完全自包含的上下文包**（`Ti` 目标与对应规格段落 + 本条 `git diff` + 已跑通命令 + 已排除假设）：
   - **Reviewer 禁挑刺红线**：只读审查**仅允许因确定性缺陷**（漏实现规格、逻辑/并发 Bug、鉴权或 `WithinTx` 事务遗漏、假测试）打回；**严禁以主观代码风格或额外优化建议打回**。
   - 若被第 2 次打回，同样先走只读根因诊断再修改；单条任务审查打回上限为 **3 轮**。
3. **原子提交或干净回滚（严禁带病提交）**：
   - **通过**：将 `Ti` 标为 `[x]`，在 `auto/<slug>` 分支执行一次干净的原子 `git commit`，进入 `T(i+1)`。
   - **单条熔断**：若门禁修 3 次未过或审查 3 轮仍有确定性缺陷，**必须执行 `git restore` / 清理未跟踪脏文件，将工作区完整回退到上一条已全绿的提交状态**，把 `Ti` 标为 `[!]` 并记录根因：
     - 若后续任务**不依赖** `Ti`，可跳过继续执行后续独立任务；
     - 若后续任务**强依赖** `Ti`（如底层表或核心契约未就绪），**立即终止循环**，绝不在坏代码之上继续堆叠。

## 5. 全局终审与三件套 PR 交付
- 循环结束后执行全量 `make check-all && make test-int` 及一次全局只读核对，推送 `auto/<slug>` 分支并创建 PR。PR 正文固定输出三件套供人工快速验收：
  1. **规格逐条核对表**（各功能点完成状态与对应 commit）；
  2. **执行期默认假设清单（Assumptions）**；
  3. **`[!]` 熔断遗留项与全局终审结论**（低风险且 0 遗留的 PR 将由 CI 自动 Squash 合入 `main`）。
